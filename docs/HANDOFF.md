# Handoff

A local, self-hosted AI website builder (a Replit-style editor) that builds sites with an agent running on a Claude subscription, a vendored design system, templates, and a self-checking loop. This file is everything a new person or a fresh session needs. Nothing here contains secrets or personal data.

State at handoff: `main` is up to date with PRs #7 to #14 merged. 35 tests pass, `tsc` is clean, lint has 0 errors (7 upstream warnings), production build passes.

## What it does
1. You ask for a site in the editor. The agent (Claude via the Claude Agent SDK, using the logged-in `claude` CLI, no API key) plans, picks a starter template, writes files, generates photos, and checks its own page in a real browser before it may finish.
2. Sites are static (index.html + site.css + script.js + images/) styled with the bm-design-system (Tailwind v4). The preview injects a Tailwind runtime; the **production export** precompiles everything.
3. Everything the agent writes is gated: CSS must compile, files must exist, invented content must be marked `data-sample`, the latest version must have been looked at in headless Chrome with no errors.

## Run it
```
docker start replit-clone-pg                       # Postgres 17 on 127.0.0.1:5433 (restart policy: unless-stopped)
HOST=<lan-ip> scripts/dev.sh                       # app on http://<lan-ip>:3000 (HOST defaults to 127.0.0.1)
```
Not started automatically at boot. Production build: `npm run build`. Setup from scratch: `docs/LOCAL_SETUP.md`.

`.env.local` keys (values are secrets, never commit): `DATABASE_URL`, `BETTER_AUTH_URL`, `BETTER_AUTH_SECRET`, `NEXT_PUBLIC_APP_URL`, `TRUSTED_ORIGINS`, `ALLOWED_DEV_ORIGINS`, `ENABLE_DEV_EMAIL_AUTH`, `NEXT_PUBLIC_ENABLE_DEV_EMAIL_AUTH`, `ALLOWED_EMAILS` (only these can sign up), `CLAUDE_CODE_PATH`. `ANTHROPIC_API_KEY` is no longer used and can be deleted.

Needs on the host: Docker, Node 22, bun, a logged-in `claude` CLI (agent), a logged-in `codex` CLI (image generation), Google Chrome at `/usr/bin/google-chrome` or `CHROME_PATH` (render check).

## Commands
```
bun test tests/                                    # 35 tests (+1 live image test: RUN_LIVE_IMAGE_TEST=1)
node scripts/verify-bm-skills.mjs                  # vendored skills match the pinned commit
bun run scripts/snapshots.ts list|create|restore <projectId> <artifactSlug> [id]

node scripts/serve-dist.mjs dist 4500              # test an export locally with its real headers
node scripts/generate-images.mjs spec.json outdir  # batch photos via Codex
```
Data lives in `.data/` (git-ignored): `project-workspace/<projectId>/<artifact>/` (site files), `snapshots/`. Database: Docker volume `replit-clone-pgdata`. Back both up together (`pg_dump` + tar of `.data/project-workspace`).

## Decisions already made
- Subscription auth, no API keys (agent via Claude CLI, images via Codex CLI).
- Strict gates over trust: the agent cannot finish with unmarked invented content, missing or remote images, uncompilable CSS, or an unchecked page.
- Errors block, warnings block once so the agent must acknowledge them.
- Photos are AI-generated by default and are illustrative; real photos replace them through the Images panel.
- No AI-generated labelling on sites (owner decision); the agent never presents generated people as real clients or staff.
- Reference-site capture (agent sees URLs the owner pastes) is approved in principle, limited to URLs in the owner's own messages. Not built.

## Known limits and risks
1. **Previews run on the app's own origin** with the user's cookie (issue #4, SECURITY_AUDIT R1/R1b). Do not expose the editor publicly until previews move to a separate cookieless origin.
2. Generated sites' forms send nothing until a `data-endpoint` is set; the export warns. The privacy notice is a draft needing legal review.
3. The design system is not wired into React (esbuild) artifacts; build content sites as static.
4. The agent cannot judge taste: it checks defects, not beauty. Review designs yourself.
5. Rate limits are shared with the owner's own Claude and Codex use. Whether a self-hosted tool on a subscription login is within Anthropic's terms is the owner's call to check.
6. `bm-skills` and `build-new` have no LICENSE file (README says free to use). This repo is public and contains a vendored copy of bm-skills.
7. Automated accessibility scores (Lighthouse 100) missed two invisible-text bugs; only screenshots and the pixel check caught them. Trust the render check and your eyes over a score.

## Lessons worth keeping
- Verify with the real thing: every "done" in this project was tested in a real browser or against the real service, and several first attempts failed (a stdin hang, a stray import, an unregistered tool, invisible text). Never close a claim on a green summary.
- Stacked PRs can merge into the wrong base silently; confirm that `main` actually contains the branch (`git diff --stat origin/main <branch>` is empty).
- Tests that touch shared module state must use the root the module resolved, and must delete their own fixtures.
- Keep personal data out of the public repo (LAN address, emails, business content). `.data/` and `.env.local` are ignored; check `git grep` before pushing.
